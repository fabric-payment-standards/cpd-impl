Two valid paths, shown side by side

Call the codec, or carry it with you — both are correct.

Every code sample below is shown two ways: calling a hosted (or self-hosted) codec service over HTTP, and doing the equivalent work locally — via the installed @fpsf/cpd package for TypeScript, or a small, copy-pasteable parser for Flutter, where no package exists yet. Neither path is "the right one." They trade off differently, and real apps often use both.

Why call the hosted codec

One implementation, one place to fix a bug or track a spec revision. No risk of your own parser silently drifting from CPD-003 — the closed-parameter rejection rules and the strict percent-decoding behavior (§7.3 — never treat + as space) are easy to get subtly wrong by hand, and your platform's default query-string parser (JavaScript's URLSearchParams, Dart's Uri.splitQueryString) gets exactly this wrong by default.

Why carry it locally

Offline-capable apps, air-gapped environments, or just avoiding a network round trip before you can even show a "scanning…" state. The TypeScript reference implementation is a real, installable package. The Flutter code below is a small, self-contained, spec-conformant parser you can paste directly into your codebase — not a placeholder.

"External" is relative to the client, not to you. The codec service in every example below is the exact reference implementation from FPSF-CPD-001 — you can run it yourself (npm install && npm run dev from the @fpsf/cpd package), deploy it inside your own infrastructure, and point your client app at that. "External" just means it's a separate process from your mobile or web client, not that it has to be someone else's server.
Architecture

Where the codec sits relative to your client and your backend.

Client (React web app, or Flutter mobile app)
      │
      │  scans a QR code / opens a deep link → gets a raw "fpsf-pay:…" string
      ▼
Codec Service            (this repo's reference implementation — yours to host)
  POST /v1/payments/uri/parse    → identify the form, without committing to a full decode
  POST /v1/payments/uri/decode   → Forms 1–2: a canonical Payment. Form 3: an unresolved token.
  POST /v1/payments/encode       → construct Form 1 + Form 2 URIs from a Payment
  POST /v1/payments/uri/token    → wrap an already-minted token + signature as a Form 3 URI
      │
      │  Form 3 only: the codec never resolves a token — that's your call
      ▼
Your Resolution Endpoint       (your own backend — CPD-003 §12.4, out of scope for this spec)
  exchanges { value, sig } for the actual payload, e.g. another fpsf-pay: URI
  or a raw Payment/CPR JSON body — which then goes back through the codec above

The codec never mints or verifies a Form 3 signature, and never resolves a token into a payload — those are deliberately your application's concern (CPD-003 §12.4). Everything else — parsing, closed-vocabulary validation, and Forms 1–2 decoding — is exactly what the codec exists to take off your plate.

Client code

TypeScript (React) and Flutter, side by side.

Both frameworks cover the same four jobs: receiving and parsing a link, resolving a Form 3 reference, constructing a link (typically the payee side of a checkout or invoicing flow), and — Form 3 only — why minting a signed token stays on your backend, never in the client.

1. Receiving and parsing a link — Forms 1 & 2

A React app rarely needs to know in advance which form it received — /v1/payments/uri/decode (hosted) and decodeURI (installed) both resolve Forms 1–2 transparently and only special-case Form 3.

Hosted codec
Installed @fpsf/cpd
// usePaymentFromUri.ts — a React hook wrapping the hosted codec
import { useEffect, useState } from "react";

type DecodedLink =
  | { status: "loading" }
  | { status: "error"; message: string }
  | { status: "payment"; payment: Record<string, unknown> }
  | { status: "token"; value: string; signatureAlg: string; signature: string };

export function usePaymentFromUri(uri: string, codecBaseUrl: string): DecodedLink {
  const [result, setResult] = useState<DecodedLink>({ status: "loading" });

  useEffect(() => {
    let cancelled = false;
    setResult({ status: "loading" });

    fetch(`${codecBaseUrl}/v1/payments/uri/decode`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ uri }),
    })
      .then(async (res) => {
        const body = await res.json();
        if (!res.ok) throw new Error(body.error?.message ?? "decode failed");
        if (cancelled) return;
        if (body.form === "token") {
          setResult({ status: "token", value: body.value, signatureAlg: body.signatureAlg, signature: body.signature });
        } else {
          setResult({ status: "payment", payment: body.payment });
        }
      })
      .catch((err) => { if (!cancelled) setResult({ status: "error", message: String(err) }); });

    return () => { cancelled = true; };
  }, [uri, codecBaseUrl]);

  return result;
}
// PaymentLinkPreview.tsx — display-and-confirm, per CPD-003 §12.1
export function PaymentLinkPreview({ uri, codecBaseUrl }: { uri: string; codecBaseUrl: string }) {
  const result = usePaymentFromUri(uri, codecBaseUrl);

  if (result.status === "loading") return <p>Reading payment link…</p>;
  if (result.status === "error") return <p role="alert">Couldn't read this link: {result.message}</p>;
  if (result.status === "token") return <ResolveTokenLink {...result} />; // see step 2

  const p = result.payment as any;
  return (
    <div>
      <p>Pay <strong>{p.value.amount} {p.value.asset}</strong> to <strong>{p.payee.id}</strong></p>
      {p.intent?.reference && <p>Reference: {p.intent.reference}</p>}
      {/* never act automatically — require an explicit tap before authorizing */}
      <button onClick={() => onConfirm(p)}>Confirm and continue</button>
    </div>
  );
}
// npm install @fpsf/cpd
import { decodeURI, UnresolvedTokenUriError } from "@fpsf/cpd";

function readPaymentLink(uri: string) {
  try {
    const payment = decodeURI(uri); // resolves Forms 1 & 2 directly
    return { status: "payment" as const, payment };
  } catch (err) {
    if (err instanceof UnresolvedTokenUriError) {
      // Form 3 — no embedded payload; resolve out of band, see step 2
      return { status: "token" as const, value: err.value, signatureAlg: err.signatureAlg, signature: err.signature };
    }
    throw err; // malformed URI — CpdUriError
  }
}

No network round trip before you know which form you have, and no dependency on a running codec service — at the cost of one more package in your bundle, and being responsible for updating it when CPD-003 changes.

2. Resolving a Form 3 reference

Form 3 — Ephemeral Token + Signature

Both parsing paths above hand you back { value, signatureAlg, signature } for a Form 3 URI — identically, since resolution itself is not part of CPD-003 (§12.4). What you do next is entirely your application's own resolution endpoint.

// ResolveTokenLink.tsx — your resolution endpoint, not the codec's
async function resolveToken(value: string, signatureAlg: string, signature: string) {
  // Your own backend — e.g. reusing the Stablecoin Stack's Ephemeral Token
  // pattern (FPSF-SS-001 §5.2, §8.3), or any resolution mechanism you define
  // (CPD-003 §12.4 deliberately leaves this open).
  const res = await fetch(`https://your-app.example/api/resolve-payment-link?token=${value}`);
  if (!res.ok) throw new Error("could not resolve payment link");
  const { uri: resolvedUri } = await res.json(); // e.g. another fpsf-pay:cpd-json-v1.… URI
  return resolvedUri;
}

function ResolveTokenLink({ value, signatureAlg, signature }: { value: string; signatureAlg: string; signature: string }) {
  // Feed the resolved URI straight back into usePaymentFromUri / decodeURI —
  // it will always be a Form 1 or Form 2 URI, never another Form 3 reference.
  const [resolvedUri, setResolvedUri] = useState<string | null>(null);
  useEffect(() => { resolveToken(value, signatureAlg, signature).then(setResolvedUri); }, [value]);
  if (!resolvedUri) return <p>Resolving payment reference…</p>;
  return <PaymentLinkPreview uri={resolvedUri} codecBaseUrl={CODEC_BASE_URL} />;
}
The signature authenticates the reference, not the payment. Per CPD-003 §12.2, signature only proves the token wasn't tampered with in transit — it says nothing about whether resolveToken's endpoint is trustworthy or whether the resolved payload has changed since the token was minted. TLS to a resolution endpoint you control is what actually protects this step.

4. Minting a Form 3 token — backend only, not client code

Form 3 — Ephemeral Token + Signature
Never in the client. Producing sig requires access to your issuing system's private signing key. That key MUST NOT ship inside a React web bundle or a mobile app. The snippet below runs on your backend — the codec's /v1/payments/uri/token endpoint only performs the final wire-format wrapping (CPD-003 §8), never the signing itself. 
// server-side (Node.js) — mints, signs, then wraps as a Form 3 URI
const value = mintEphemeralToken();               // your own session/reference logic
const signature = signWithIssuerKey(value);        // e.g. Ed25519, per CPD-003 §12.3

const res = await fetch(`${codecBaseUrl}/v1/payments/uri/token`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ value, signatureAlg: "ed25519", signature }),
});
const { uri } = await res.json(); // fpsf-pay:token?value=...&sig=ed25519:...
No published Dart package exists yet. The TypeScript side has a real, installable @fpsf/cpd package. Flutter does not — yet. Every "local" snippet below is copy-pasteable reference code, not a dependency you install, which is exactly the "copy-pasted" path this guide is meant to cover honestly rather than pretend a package exists.

1. Receiving and parsing a link — Forms 1 & 2

Hosted codec
Local parser (copy-paste)
// pubspec.yaml: dependencies: http: ^1.2.0
// cpd_codec_client.dart
import 'dart:convert';
import 'package:http/http.dart' as http;

class CpdCodecClient {
  final String baseUrl;
  CpdCodecClient(this.baseUrl);

  Future<Map<String, dynamic>> decodeUri(String uri) async {
    final res = await http.post(
      Uri.parse('$baseUrl/v1/payments/uri/decode'),
      headers: {'Content-Type': 'application/json'},
      body: jsonEncode({'uri': uri}),
    );
    final body = jsonDecode(res.body) as Map<String, dynamic>;
    if (res.statusCode != 200) {
      throw Exception(body['error']?['message'] ?? 'decode failed');
    }
    return body; // { form: "envelope-or-stringified", payment: {...} }
                // or  { form: "token", value, signatureAlg, signature, resolved: false }
  }
}
// payment_link_preview.dart — display-and-confirm, per CPD-003 §12.1
class PaymentLinkPreview extends StatefulWidget {
  final String uri;
  final CpdCodecClient codec;
  const PaymentLinkPreview({super.key, required this.uri, required this.codec});
  @override
  State<PaymentLinkPreview> createState() => _PaymentLinkPreviewState();
}

class _PaymentLinkPreviewState extends State<PaymentLinkPreview> {
  late final Future<Map<String, dynamic>> _future = widget.codec.decodeUri(widget.uri);

  @override
  Widget build(BuildContext context) {
    return FutureBuilder<Map<String, dynamic>>(
      future: _future,
      builder: (context, snapshot) {
        if (!snapshot.hasData && !snapshot.hasError) {
          return const Text('Reading payment link…');
        }
        if (snapshot.hasError) {
          return Text("Couldn't read this link: ${snapshot.error}");
        }
        final body = snapshot.data!;
        if (body['form'] == 'token') {
          return ResolveTokenLink(
            value: body['value'], signatureAlg: body['signatureAlg'],
            signature: body['signature'], codec: widget.codec,
          );
        }
        final p = body['payment'] as Map<String, dynamic>;
        final value = p['value'] as Map<String, dynamic>;
        final payee = p['payee'] as Map<String, dynamic>;
        return Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text('Pay ${value['amount']} ${value['asset']} to ${payee['id']}'),
            // never act automatically — require an explicit tap before authorizing
            ElevatedButton(onPressed: () => onConfirm(p), child: const Text('Confirm and continue')),
          ],
        );
      },
    );
  }
}

A minimal, spec-conformant parser — closed-vocabulary rejection and all — with no dependency beyond dart:core. It deliberately does not use Uri.splitQueryString, which follows the HTML form convention and treats + as a literal space; CPD-003 §7.3 forbids exactly that.

// fpsf_pay_uri.dart — copy this file into your project
class ParsedFpsfPayUri {
  final String form; // 'envelope' | 'stringified' | 'token'
  final String? codec, payload, json, value, signatureAlg, signature;
  ParsedFpsfPayUri._(this.form, {this.codec, this.payload, this.json,
      this.value, this.signatureAlg, this.signature});
}

class CpdUriException implements Exception {
  final String message;
  CpdUriException(this.message);
  @override
  String toString() => 'CpdUriException: $message';
}

final _codecTokenRe = RegExp(r'^[A-Za-z0-9-]{1,32}$');
final _base64UrlRe = RegExp(r'^[A-Za-z0-9_-]+$');
final _algIdRe = RegExp(r'^[A-Za-z0-9-]{1,16}$');

Map<String, String> _splitQueryStrict(String query) {
  if (query.isEmpty) throw CpdUriException('empty query string');
  final out = <String, String>{};
  for (final segment in query.split('&')) {
    final eq = segment.indexOf('=');
    if (eq == -1) throw CpdUriException('malformed query segment (no "="): "$segment"');
    final key = segment.substring(0, eq);
    if (out.containsKey(key)) throw CpdUriException('duplicate query parameter "$key"');
    out[key] = segment.substring(eq + 1);
  }
  return out;
}

void _assertExactKeys(Set<String> keys, List<String> required, String form) {
  final req = required.toSet();
  for (final k in keys) {
    if (!req.contains(k)) throw CpdUriException('unrecognized query parameter "$k" for Form $form');
  }
  for (final r in required) {
    if (!keys.contains(r)) throw CpdUriException('missing required query parameter "$r" for Form $form');
  }
}

// Strict RFC 3986 percent-decoding — Uri.decodeComponent never treats
// "+" as space, unlike Uri.splitQueryString. That distinction is the
// whole reason this function exists instead of using the built-in one.
String _percentDecodeStrict(String value) {
  try {
    return Uri.decodeComponent(value);
  } catch (_) {
    throw CpdUriException('malformed percent-encoding');
  }
}

ParsedFpsfPayUri parseFpsfPayUri(String uri) {
  const prefix = 'fpsf-pay:';
  if (!uri.startsWith(prefix)) throw CpdUriException('URI must start with "$prefix"');
  final body = uri.substring(prefix.length);
  final qIndex = body.indexOf('?');

  if (qIndex == -1) {
    final dot = body.indexOf('.');
    if (dot == -1) throw CpdUriException('Form 1 URI must contain "."');
    final codec = body.substring(0, dot);
    final payload = body.substring(dot + 1);
    if (!_codecTokenRe.hasMatch(codec) || codec == 'token') {
      throw CpdUriException('invalid codec token "$codec"');
    }
    if (!_base64UrlRe.hasMatch(payload)) throw CpdUriException('Form 1 payload must be base64url');
    return ParsedFpsfPayUri._('envelope', codec: codec, payload: payload);
  }

  final head = body.substring(0, qIndex);
  final query = body.substring(qIndex + 1);

  if (head == 'token') {
    final params = _splitQueryStrict(query);
    _assertExactKeys(params.keys.toSet(), ['value', 'sig'], '3');
    final value = params['value']!;
    final sig = params['sig']!;
    if (!_base64UrlRe.hasMatch(value)) throw CpdUriException('Form 3 "value" must be base64url-safe');
    final colon = sig.indexOf(':');
    if (colon == -1) throw CpdUriException('Form 3 "sig" must be "<alg-id>:<signature>"');
    final alg = sig.substring(0, colon);
    final sigBody = sig.substring(colon + 1);
    if (!_algIdRe.hasMatch(alg) || !_base64UrlRe.hasMatch(sigBody)) {
      throw CpdUriException('invalid Form 3 signature');
    }
    return ParsedFpsfPayUri._('token', value: value, signatureAlg: alg, signature: sigBody);
  }

  if (head.contains('.') || !_codecTokenRe.hasMatch(head)) {
    throw CpdUriException('invalid codec token "$head"');
  }
  final params = _splitQueryStrict(query);
  _assertExactKeys(params.keys.toSet(), ['envelope'], '2');
  final json = _percentDecodeStrict(params['envelope']!);
  return ParsedFpsfPayUri._('stringified', codec: head, json: json);
}

This gets you a validated, form-identified ParsedFpsfPayUri. For Forms 1–2, you'd still base64url- or JSON-decode payload/json yourself to get the underlying Payment fields — reasonable for a trusted, controlled environment; if you want a battle-tested canonicalization/validation layer too, that's exactly what the hosted codec path already gives you.

class ResolveTokenLink extends StatefulWidget {
  final String value, signatureAlg, signature;
  final CpdCodecClient codec;
  const ResolveTokenLink({super.key, required this.value,

class _ResolveTokenLinkState extends State<ResolveTokenLink> {
  late final Future<String> _resolvedUri = _resolve();

  Future<String> _resolve() async {
    // Your own backend — CPD-003 §12.4 leaves resolution out of scope,
    // deliberately. Re-using FPSF-SS-001's Ephemeral Token exchange
    // (checkout-public-widget) is one concrete, already-existing precedent.
    final res = await http.get(
      Uri.parse('https://your-app.example/api/resolve-payment-link?token=${widget.value}'));
    final body = jsonDecode(res.body) as Map<String, dynamic>;
    return body['uri'] as String; // always Form 1 or 2, never another Form 3
  }

  @override
  Widget build(BuildContext context) {
    return FutureBuilder<String>(
      future: _resolvedUri,
      builder: (context, snapshot) {
        if (!snapshot.hasData) return const Text('Resolving payment reference…');
        return PaymentLinkPreview(uri: snapshot.data!, codec: widget.codec);
      },
    );
  }
}

Before you ship

Client integration checklist.

You never act on a decoded payload without an explicit user confirmation — CPD-003 §12.1, §12.5, and CPD-002 §11.1 all require this, on every platform.
Form 3 is handled as a distinct branch, not an error — an UnresolvedTokenUriError or a { "form": "token" } response is expected, ordinary control flow, not a failure state.
You never use your platform's default form-encoded query parser (URLSearchParams, Uri.splitQueryString) for Form 2's envelope parameter — both treat + as space, which CPD-003 §7.3 forbids.
Unknown query parameters are rejected, not ignored, if you're parsing locally — CPD-003 §10 is a hard requirement, not a suggestion.
No signing key ever ships inside a client bundle or mobile binary — Form 3 minting stays server-side, always.
Your resolution endpoint (Form 3) is documented as your own, not confused with the codec's — the codec never resolves a token, by design.
You've registered the fpsf-pay: scheme with the OS on both platforms (iOS Info.plist, Android intent-filter) if you want deep links to open your app directly.
